# OmniSight — Working Philosophy

> หลักการทำงานที่ได้จากประสบการณ์จริงในโครงการนี้  
> ไม่ใช่กฎที่ตั้งขึ้นลอยๆ — ทุกข้อมาจากบทเรียนที่เจ็บปวดจริง

---

## 1. "แก้แล้ว commit ทันที — ไม่มีค้าง"

> *"Code ที่ไม่ได้ commit คือ code ที่ไม่มีอยู่จริง"*

uncommitted changes สะสม → user งง → กลัว commit → ปล่อยทิ้ง → สุดท้ายมีปัญหา  
วงจรนี้ตัดได้ด้วยนิสัยเดียว: **แก้เสร็จ → commit ก่อนทำอย่างอื่น**

ลำดับที่ถูก:
```
แก้โค้ด → git diff → git add → git commit → แล้วค่อยทำงานถัดไป
```

---

## 2. "อ่านก่อน เขียนทีหลัง"

> *"ถามก่อนว่ามีอยู่แล้วหรือยัง ก่อนจะสร้างใหม่"*

Claude อาจทำงานอยู่ใน worktree ที่มีโค้ดเก่ากว่า main repo  
ก่อน implement ทุกครั้ง — **อ่าน main repo ก่อนเสมอ**

```bash
# เช็คก่อนทุกครั้ง
grep -r "feature_name" F:\programming\python\OmniSight\backend\
```

ถ้ามีอยู่แล้ว → ไม่ทำซ้ำ → ประหยัด tokens และเวลา

---

## 3. "รู้สถานะก่อนลงมือ"

> *"ไม่มีนักบินคนไหนบินโดยไม่ทำ pre-flight check"*

เริ่ม session ใหม่ทุกครั้ง:
```bash
cd "F:\programming\python\OmniSight"
git status            # มี uncommitted อะไรบ้าง?
git log --oneline -3  # อยู่ที่ sprint ไหน?
```

อ่าน `CLAUDE.md` ก่อนทุกครั้ง — มันคือ cockpit ของโครงการนี้

---

## 4. "จบสะอาด — เริ่มสะอาด"

> *"สภาพที่ทิ้งไว้คือสภาพที่คนถัดไป (หรือตัวเองในวันพรุ่งนี้) จะเจอ"*

จบ session:
- `git status` → "nothing to commit, working tree clean"
- เอกสารอัปเดตแล้ว (SPRINT_LOG, CLAUDE.md)
- push แล้ว (ถ้าได้รับอนุมัติ)

---

## 5. "ทำน้อย แต่ทำให้สมบูรณ์"

> *"feature ที่ทำครึ่งเดียวแย่กว่าไม่ทำเลย"*

ถ้าเวลาไม่พอ → บอก user ก่อน → อย่าทำครึ่งๆ กลางๆ แล้วทิ้งไว้  
ทุก task ที่รับทำต้องมี: โค้ดทำงาน + commit + เอกสาร

---

## 6. "ห้าม push โดยไม่ขออนุญาต"

> *"repository คือทรัพย์สินของ user ไม่ใช่ของ AI"*

GitHub push ทุกครั้งต้องรอ user บอก "push ได้"  
ไม่มีข้อยกเว้น

---

## 7. "บันทึกทุกบทเรียน — ก่อนลืม"

> *"บทเรียนที่ไม่ได้บันทึกคือบทเรียนที่ต้องเรียนซ้ำ"*

เมื่อเกิดปัญหา/แก้ปัญหาได้:
1. บันทึกใน `memory/feedback_*.md` (จำข้ามทุก session)
2. บันทึกใน `CLAUDE.md` (session AI ถัดไปอ่านทันที)
3. บันทึกใน `SPRINT_LOG.md` (ประวัติโครงการ)
